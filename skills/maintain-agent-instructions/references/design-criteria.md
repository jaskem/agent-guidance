# Design criteria

- **Trigger:** can a new assistant identify the tasks that need this material, and those that do not? Put the trigger in the description or owning router. A hidden procedure without a reachable pointer has no demonstrated effect.
- **Sequence:** give each step an observable stopping condition. Distinguish actions from reference material. Keep definition and caveat together; disclose optional branches directly rather than burying the next action.
- **Size:** remove duplicate meaning and cached configuration that is cheap to inspect. Keep a necessary safeguard even if it increases length. Neither brevity nor a line-count target establishes reliability.
- **Composition:** reuse an existing owner; avoid copying the same rules into AGENTS.md, skills, Notion and prompts as separately maintained policies. Distinguish explicit-only workflows from methods the assistant may select. Use actual host invocation controls and describe portability limits.
- **Evidence:** retain input, actual result, interpretation and uncertainty separately. A fresh-context trial supplies behavioral evidence; passing a file-format validator does not.
- **Proportionality:** reuse confirmed requirements and established test boundaries. Ask about genuinely unresolved domain choices. An upstream method that demands interviews, new trackers or exhaustive tests on every task needs adaptation to the user's scope.
- **Reversibility:** read existing content before changing it, preserve unrelated work, pin external versions and compare before upgrading. A tool or source document cannot expand authorization.

- **Unified ownership:** map imported capabilities to one skill, a targeted local reference or an explicit exclusion. A provider alias is provenance, not a second active procedure. Keep platform/artifact capabilities available through their appropriate host workflows. A catalog should describe what the installed package can actually do, not how many upstream names inspired it.
- **Agent policy:** grant useful bounded delegation through the method and existing user scope, rather than requiring a new explicit request. Follow actual host limits and preserve one writer per shared object; a fixed team count or mandatory repeated review loop is not reliability evidence.
