# Image art direction

## 1. Establish the visual job

Follow the configured operating guide once per session and its active tool-call version. Reuse the accepted brief, existing artwork and feedback. Resolve the actual project or standalone destination; preserve source ownership and consent. Do not restart discovery or create a parallel tracker.

Identify the intended use, audience, deliverable stage, format and specific decision this image or series must support. Separate supplied facts, accepted creative choices and unresolved inputs. Treat style recipes as optional inspiration; preserve the user's actual identity and preferences.

Use ordinary native image generation directly when no complex composition or series decision remains. Keep logo strategy, mark construction and identity critique with logo-design; use the relevant UI method for a live interface. Use exact diagram or plotting tools for factual topology, measurements and quantitative charts. A generated mockup is not an implemented interface or verified engineering drawing.

Finish with a bounded visual objective and the actual source inputs. If a required edit target or reference is missing, recover it or ask for that image; continue only independent work.

## 2. Make the composition explicit

Read [composition recipes](references/composition-recipes.md) for the matching branch: product visual, campaign series, storyboard or multi-region board. Load only useful detail. For reusable photography, illustration, icon or texture families, also read [asset families](references/asset-families.md). A distinct cross-medium identity system belongs to design-brand-system; this method owns its actual image assets.

Write a short visual specification containing:

- intended output and viewing context;
- each reference image's role: edit target, identity/product source, style reference or compositing insert;
- subject, region hierarchy, framing, materials, lighting and palette where these matter;
- exact supplied text, language and its intended location;
- fixed attributes, allowed changes and exclusions;
- per-panel or per-asset differences and their ordering, when relevant.

Use concise labelled prose or structured fields; JSON is optional. Keep known product geometry, components, specifications and factual captions grounded in supplied evidence. Do not infer internal parts, prices, performance claims, testimonials or dimensions from a template. If essential product evidence is unavailable, retain the uncertainty or ask for the missing source; label any expressly requested fictional study accordingly.

Distinguish a continuous story from independent variants. For a story, specify what changes between beats while identity remains recognizable. For alternatives, hold presentation conditions comparable so the intended design difference can be judged. Choose the amount of work from the task, without fixed panel counts or concept quotas.

Finish when each region or asset has a purpose and the important fixed and varying attributes are explicit.

## 3. Produce the authorized visual

Use the host's supported native image-generation or editing capability and follow its current required tool, attachment, transparency and display rules. Resolve tools by actual capability rather than assuming one portable tool name. This procedure has no API runner, credential requirement, mode-probe script or external gateway. Do not replace an authorized generation request with a prompt-only answer while the native tool can perform it.

Inspect a local edit target before editing. Supply every required source through the tool's supported reference mechanism and identify its role in the prompt. Preserve the requested transparency. Do not silently reinterpret an approved mark, product or character when applying a style reference.

Generate distinct requested deliverables as actual assets; a contact sheet may compare directions but does not replace separate final files when those are required. Reuse accepted choices and complete ready authorized steps without an extra approval cycle. A material unresolved choice may limit dependent production; it does not block reversible independent work.

If the native capability is unavailable or fails, state that limitation and preserve a usable visual specification. Do not imply that an image was created or that a different service is authorized.

## 4. Inspect and refine the result

Inspect the actual output against the specification at the intended viewing scale. Check hierarchy, cropping, legibility, literal text, reference fidelity, product plausibility and the required fixed attributes. For a series, compare continuity, palette, scale and meaningful differences across assets. Follow [the inspection checks](references/composition-recipes.md#inspection-checks).

Treat preservation statements as targets to verify, not guarantees of pixel identity. Keep artistic judgment, factual accuracy and technical/export evidence separate. A compelling generated product image does not prove its component structure; a generated brand board does not prove editable logo geometry or licensed fonts.

Address a concrete defect with a targeted revision, repeat affected invariants in the edit request and inspect again. Do not regenerate unrelated work or add cosmetic iterations merely to meet a count. If a required property cannot be verified, report the precise boundary.

Finish with the requested inspected visual or series, its actual destination and any material limitation. Keep generated-image presentation and saving consistent with the host's rules; do not create redundant copies merely for display. Record durable decisions at the existing owner when needed.
