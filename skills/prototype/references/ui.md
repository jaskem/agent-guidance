# UI comparison

Use two or three structurally distinct alternatives when a comparison is useful. Vary information hierarchy, action placement or interaction; a color change alone does not test a layout decision. For a single precise usability question, one interactive experiment can suffice.

Prefer the real surrounding layout, labels, representative density and viewport. Reuse the design system. Provide an obvious variant switch without interfering with inputs, keyboard controls or accessibility. Show the same task and data in each alternative.

Check the primary interaction, relevant empty/error/selected states and mobile layout when in scope. Keep prototype navigation visibly separate from product controls. Record which question each alternative settles. Remove experimental controls from production integration.

Represent loading, error, pending and disabled feedback when needed to judge the chosen interaction. Preserve native semantics, meaningful control names, keyboard activation and focus return; a custom-looking control need not become inaccessible. Check the actual target platform rather than imposing browser/mobile breakpoints on a native desktop question.
