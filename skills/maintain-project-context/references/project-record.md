# Project record

Use the existing home and its field names. Add only missing information that supports navigation or resumption.

| Field | Evidence to retain |
| --- | --- |
| Identity | Project name, verified aliases, canonical source ID/URL, existing home |
| Outcome | User-confirmed purpose; unresolved scope labelled |
| Owners | Separate code, tasks, decisions and durable context locations |
| Snapshot | Material fact, observed date, exact source/revision, verification limit |
| Next action | Existing task/checkpoint link and genuine blocker, if any |
| Coverage | Sources enumerated/fetched, pagination completion, inaccessible surfaces |

For multiple projects, keep one compact index linking these homes. Keep detailed records with their owner. A repository-backed project can use a Notion task database or GitHub issues. Choose from observed ownership, not code location or the tool used to create the index.

If two homes share the same source ID, inspect both before selecting the established owner. Preserve unique content and links; report any consolidation needing a user decision. If matching names point to different source IDs, keep them separate until evidence resolves the relationship.

## Keep context useful across methods

When a source or installed method changes, update the affected entrypoint and version/distribution pointer. Keep historic evidence dated rather than erasing it. Do not copy a complete provider catalog or product plan into each project home.

For an observed context failure, identify the missing, stale, conflicting or irrelevant input and its single owner. Route an instruction defect to maintain-agent-instructions; a project-home mismatch remains here. A material source gap is a limit on the dependent claim, not a reason to scan every connected source.
