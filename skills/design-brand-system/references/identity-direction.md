# Identity diagnosis and direction

## Diagnose the actual identity

Use only evidence relevant to the brief. Inspect the supplied assets and actual applications, noting source, version, surface and missing coverage.

| Question | Evidence and distinction |
| --- | --- |
| What is intended? | Accepted audience, purpose, qualities and positioning; separate current decisions from proposals. |
| What is practiced? | Actual type, color roles, imagery, layout, tone and repeated patterns across representative surfaces. |
| Where does it fail? | Separate a weak asset from a sound asset placed badly, stale guidelines, inconsistent implementation or unavailable materials. |
| What remains useful? | Preserve recognizable working elements and established product contracts; novelty is not an objective by itself. |
| What should change? | Map each priority observation to an outcome, affected scope and appropriate check. |

For a brand comparison, establish the relevant comparison set from verified context and inspect it. Compare like contexts and dates. A web execution problem is not automatically a weak identity; a distinctive mark does not establish usable product UI. Report evidence and limits instead of inventing a score.

A diagnosis can recommend preserving, evolving or replacing parts of a system. The user's accepted scope determines what is authorized; a recommendation alone is not acceptance of a rebrand.

## Translate meaning into a visual direction

Build the shortest useful chain:

1. Intended quality from the brief, with its accepted or proposed status.
2. Specific reference quality: a light pattern, structural rhythm, material, lettering characteristic or compositional relationship.
3. Abstraction: the principle to borrow rather than the reference's literal symbol or assets.
4. Product application: a concrete type, layout, asset or interaction choice and why it fits.
5. Inspection: the rendered application that lets the choice be judged.

Keep the actual audience and message central. A historical engineering reference can inform precision or structure without importing its period equipment. A humanist reference need not force serif type. Do not use a mood adjective as evidence that a design works.

Use a board or comparable applications when they resolve uncertainty. Show the same actual brand name and comparable content across alternatives, identify reference-only material, and separate exploratory references from original proposed artwork. A board of attractive unrelated images is not a system.

## Record what may flex

Use one existing source for the system and point to it from applications.

| Item | Record |
| --- | --- |
| Identity intent | Audience, use, accepted qualities and supplied claims; unresolved positioning stays open. |
| Fixed core | Approved mark files and variants, required names, semantic roles and other explicitly fixed decisions. |
| Flexible range | Allowed scale, composition, density, image crop and medium-specific expression with boundaries and reasons. |
| Application rules | Which variant/style fits which context, use and do-not-use examples, missing cases and owning decision. |
| Evidence | Actual render/source, tested conditions, open checks and the status of each important choice. |
| Maintenance | Source revision, owner and how a material change invalidates affected examples. |

Treat a user correction as evidence. Preserve its scope and reason at the responsible owner; confirm only a material unresolved generalization. Do not promote one local preference into a universal rule or require an end-of-session interview.

Reference imagery, fonts and existing marks retain their rights and usage restrictions. A lookalike search can record the tool, query, hits, assessed similarities and unchecked scope; it does not establish trademark clearance.
