# Writing phases

Choose the operation the user needs; combine phases only when the request calls for the resulting work.

| Requested operation | Useful output | Preserve |
| --- | --- | --- |
| Explore | Distinct observations, examples, candidate claims or angles | Open alternatives; no forced outline |
| Structure | A reader journey, main claim and ordered supporting material | Source meaning and concepts introduced before use |
| Draft | Coherent prose that fulfills the promised purpose | One voice, evidence boundaries and intended audience |
| Revise | A targeted clearer or better-supported passage | Deliberate choices and unrelated user edits |

Read enough of the supplied material to understand the requested scope. Do not confuse a raw fragment, verified fact, quotation, proposed conclusion and accepted decision. If a needed example or fact is absent, name the gap, use an explicitly illustrative example when suitable, or omit that claim.

A paragraph should make one useful move for the reader. Remove repetition and unexplained jumps; keep a list or table when items are parallel. Do not force a jargon metaphor, terse voice or English language merely because a source method uses it.

For saved writing, resolve the actual destination from the task and configured document workflow. Re-read before an edit; preserve source material and user changes. An ordinary chat draft does not require a new file, a local scratch path or a question about where to save it.
