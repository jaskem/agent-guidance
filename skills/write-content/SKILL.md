# Write content

## 1. Establish the requested result

Follow the configured operating guide once per session and reuse verified context. Resolve only the relevant project, work object and existing source/task owner; a standalone request needs no project scan. Resolve the audience, purpose, language, supplied material and requested phase. Use the user's stated style and Dutch when their configured preference applies. Recover answers already present before asking for a material missing choice.

A short wording correction can be answered directly. A chat draft needs no invented project, file or publishing workflow. Use an authorized destination when saving is part of the task.

## 2. Work in the requested phase

For exploration, collect useful observations and candidate material without forcing an outline. For structure, order the available ideas around what the reader needs to understand. For a draft or revision, produce coherent prose with the intended voice. Read [writing phases](references/writing-phases.md) for these distinct operations.

Do not impose a three-phase interview, require a choice for every paragraph or widen the source material merely because another writing method exists.

## 3. Build the reader's path

Read supplied source material needed for the scope. Introduce an unfamiliar concept before relying on it. Make each passage serve the purpose; use prose for connected reasoning and lists/tables for genuinely parallel material.

Use available subagents on your own initiative when a step calls for independent work or a separate investigation/review can materially improve the result; no explicit user request is needed. Give each a bounded brief and evidence target, keep one writer per shared object, follow current host capabilities, and verify the integrated result yourself.

## 4. Check meaning and evidence

Preserve the user's intent, source distinctions and deliberate wording. Verify factual claims against relevant sources, mark consequential uncertainty and separate sourced statements from illustration. Do not invent quotations, personal experiences, research findings or technical facts to fill a gap.

Revise for one voice, clear progression and useful brevity. Technical research or a product decision remains with its existing owner; flag a gap instead of deciding it through polished prose.

## 5. Return or save the actual result

Deliver the requested fragments, structure, draft or revision with only material open questions. For saved work, read the destination before a targeted change and preserve raw sources and unrelated user edits. Use the appropriate artifact/service workflow for the chosen format.

Verify a save before claiming it. A completed draft is not a published article, sent message or agreed project decision; perform those actions only when separately authorized by the task.

For provenance when updating this method, read [sources](references/sources.md).
