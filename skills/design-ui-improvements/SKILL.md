# Design UI improvements

## 1. Ground the proposal

Read the applicable project context and supplied findings. Identify the affected task, actual baseline, product constraints and existing design system. Carry evidence limits forward. Without a baseline, draw from supplied requirements as an explicitly proposed design and record the missing comparison; route an unknown-interface audit to audit-ui-ux.

Finish with a bounded objective, traceable input findings and behavior/information to preserve. The method does not authorize changing the app.

## 2. Choose the smallest useful direction

Map each priority finding to a concrete change. Reuse product vocabulary and established visual language. Change hierarchy, grouping, disclosure or feedback to support the task. Preserve necessary expert controls and data.

For a consequential unresolved choice, compare meaningful alternatives and trade-offs. Recommend with reasons; leave domain decisions needing input open while completing independent proposals. Use an existing prototype method only when interaction or state uncertainty needs an executable experiment.

Finish when every proposed change addresses an input finding and has a task-based reason.

## 3. Make the change inspectable

Use [visual handoff](references/visual-handoff.md) for before/after views, component details and tokens. Work at a stated viewport and representative density. Keep observations, annotations and proposed interfaces visibly distinct.

Show surrounding app context to judge hierarchy, plus readable details where needed. Exact geometry belongs in HTML/SVG or document drawing tools. Inspect rendered output and correct clipping, tiny labels, missing assets and inconsistent state cues. If rendering is unavailable, label the artifact an unverified draft and retain the rendering check.

Finish with a viewable artifact or explicit rendering limit, not a prose promise of a redesign.

## 4. Define acceptance and sequence

State what must remain true, what users should see/do differently and how it will be checked. Separate visual acceptance from interaction, accessibility, performance and usability validation. Screenshots verify layout in captured states; other claims need corresponding tests.

Group changes into the smallest coherent delivery slices. Use existing tasks and dependencies; record proposed work at the established tracker without treating recommendations as accepted implementation. Keep uncertain assumptions as validation work.

Finish with a visual improvement plan whose proposals, dependencies, checks and open decisions are clear. Link the baseline, output and owning tasks. Report the artifact inspected and untested states.
