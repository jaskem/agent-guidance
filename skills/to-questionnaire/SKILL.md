# Prepare a questionnaire

## 1. Establish the knowledge gap

Follow the user's configured operating guide once per session and its active tool-call version. Reuse verified context; load the relevant project, current task and source owners, refreshing affected sources after material changes or uncertain writes. If required context is inaccessible, name the gap and continue only independently supported work. Use the routed context-entry playbook when available.

Recover the intended recipient's role, what they know and the decision the answers must support. Reuse supplied recipient and project facts. Ask only for missing context that materially changes the questions; a role is sufficient for a draft without a named person. Research accessible facts first so the questionnaire targets knowledge the recipient actually holds.

Finish with a recipient role, purpose and list of unresolved facts or decisions. Do not invent a person's identity, deadlines or expected completion time.

## 2. Draft focused questions

Use [the questionnaire structure](references/questionnaire.md). Provide enough verified context for someone outside the conversation. Order essential questions first and group by theme when useful. Ask one thing per question, include response space and allow uncertainty or partial answers. Explain why an answer matters only when that prevents ambiguity or a throwaway response.

Map every requested decision to at least one useful question. Avoid leading technical assumptions, requests for secrets and facts already supplied. Label suggestions and missing context; do not fill the recipient's answers yourself. Finish with a usable draft and explicit coverage of the knowledge gap.

## 3. Deliver for the intended use

Return the draft in the requested form or save it at the existing authorized project/document destination. Read any destination before writing and verify the save. A one-off draft may stay in the conversation. Keep unanswered questions distinct from confirmed requirements when later incorporating responses.

Sending, inviting people, sharing or changing access needs the corresponding explicit user instruction; preparing a questionnaire supplies none. Report the draft, missing context and where answers would inform the existing plan.
