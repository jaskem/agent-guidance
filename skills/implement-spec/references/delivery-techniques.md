# Integrate bounded work

## Ready slices

Choose a usable result through the real interfaces, not isolated horizontal layers that cannot be accepted. Each task needs its owning requirement, inputs, outputs, dependencies and distinguishing check. Reuse the project's task schema and quality constraints. A missing device test blocks that evidence, not every unrelated task.

## Agent work and review

Delegate independently useful implementation or investigation without waiting for the user to request agents. A parent remains responsible for blocking decisions and integration. Brief a reviewer with exact base/head, current requirements and raw artifacts; do not pass intended findings. A worker's green run covers its revision and environment, not the later combined result. Read actual changes and verify the integrated acceptance before closing a parent task.

Use the current host's actual capabilities and fork/model rules. Do not require a new worker, model or fixed review-team count for every task. A separate code worktree does not isolate a shared Notion task, browser or desktop. Keep one writer per shared object and verify a stopped writer before reassigning it.

## Branches, migration and release

Preserve existing local work and the accepted branch route. Do not use reset, stage-all or cleanup examples as permission to modify unrelated changes. Confirm ownership of a temporary checkout and preserve needed evidence before removing it. Native or pre-existing isolation can suffice; failure to create a new worktree does not automatically block safe independent work.

Plan data/contract migration around actual consumers and recovery. Match dependency installation, build and CI to the real lockfiles, package manager, runner and checks. Use prepare-release for a distinct packaging/acceptance/recovery task; its result does not authorize an unrequested deployment. No fixed file count, branch age or review-loop cap replaces the accepted quality bar.
