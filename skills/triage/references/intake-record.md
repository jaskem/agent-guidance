# Intake record

Reuse existing fields for: source link/date; reported behavior; expected result; input and version; evidence and reproduction state; related task and why it matches; user effect; confidence; accepted scope; proposed action; acceptance; blockers and next action.

Deduplicate only when the same outcome, input conditions and acceptance scope are covered. Keep a recurrence distinct when a previously fixed symptom returns on another version or configuration. Preserve the new report as evidence rather than discarding it.

Useful outcomes are a ready task, evidence gathering, a linked duplicate, a confirmed existing result, or a recommendation requiring a decision. Missing information is not rejection. A deferred feature is not a permanent scope exclusion. Keep decision history at the existing owner instead of creating a second rejection knowledge base.

Completion is intake coverage plus verified record changes. It does not mean every report is fixed.
