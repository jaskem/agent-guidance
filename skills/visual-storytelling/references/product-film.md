# Product films and web loops

Reuse approved product components, screenshots or existing source where appropriate so the film shows the real product language. Identify which views are captured, recreated or illustrative. Never fabricate working controls, data, customer claims or technical capabilities for a more convincing scene. Apply an approved logo from its actual asset, preserve proportions/clear space and inspect its opening/end frame and background contrast.

Create a scene contract: communicative purpose, verified input, entry/exit state, object continuity, timing and delivery variant. Keep a deterministic frame/time source for recorded scenes and inspect intermediate states, not only the final board. Seek to known moments and confirm the returned state; a URL containing a time parameter is not proof that the app obeyed it. Use seeded randomness when reproducibility matters.

For loops, verify the seam and any pause/poster state. For an embedded web film, provide a useful poster and an appropriate reduced-motion/static experience without hiding content. For encoded delivery, separately check dimensions, duration, frame rate, codec, audio presence when requested, successful decode and representative frames. A metadata probe cannot certify correct visuals, smoothness or intelligible audio. Reuse the existing export tools; do not run unpinned installation scripts merely because a reference does so.

A hero loop, narrative MP4, presentation and interactive product animation are different outputs. Deliver only the requested variants and report untested playback/audio/encoding limits.
