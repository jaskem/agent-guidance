# Research a decision

## 1. Define the question and finish

Follow the user's configured operating guide once per session and its active tool-call version. Reuse verified context; load the relevant project, current task and source owners, refreshing affected sources after material changes or uncertain writes. If required context is inaccessible, name the gap and continue only independently supported work. Use the routed context-entry playbook when available.

Establish the decision this research serves, scope, applicable versions, constraints and existing evidence. Reuse answered questions. A stable one-step lookup needs no research report. Finish with the smallest question that could change the decision and the evidence needed to close it.

## 2. Gather and assess sources

Load the project's selected research-verification playbook when available; it owns claim classification, evidence quality, corroboration and stop criteria. Read the actual primary sources behind consequential claims: official documentation, source, standards, original research or observed product behavior. Discovery snippets alone are leads. Use current sources for mutable claims and label historical evidence by version/date.

For each relevant source record the exact link, observation/publication date when available, applicable version, supported claim and limitation using [the evidence record](references/evidence-record.md). Investigate conflicting sources against the exact question. If the routed playbook or a source is unavailable, disclose that boundary, retain only supported findings and state what would resolve the gap. Do not invent a source, quote or confidence score.

Delegate a bounded reading task only when useful and authorized; research can run sequentially. Shared findings need source pointers, not an assumed background service. Finish when available evidence answers the question or identifies a concrete unresolved dependency; stop reading when additional material is unlikely to change the decision.

## 3. Synthesize a decision brief

Separate sourced facts, interpretation, options, recommendation and uncertainty. Compare options against the user's actual constraints rather than popularity. Include counterevidence and what could change the recommendation. When evidence is insufficient, recommend a bounded next check instead of filling the gap with assumptions.

Finish with a direct answer, source-backed rationale and practical next action. A research conclusion is not acceptance of a product change.

## 4. Deliver at the existing owner

Return a concise brief with direct links. Save durable findings only at the established project/document destination within authorization; read it first and preserve prior dated conclusions. Link repository-owned evidence rather than copying it into a second master. Verify writes and report scope, source dates and unresolved access. Do not create a report, task or new tracker for every lookup.

For provenance, read [sources](references/sources.md).
