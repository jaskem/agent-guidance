## How the upstream workflow fits together

Upstream is a coordinated suite, not ten unrelated prompts:

1. `brand` always diagnoses the identity, gathers assets and selects Revolution / Evolution / Optimization.
2. `brand-strategy` supplies emotional target and references when strategy is missing or changing.
3. `creative-direction` makes the visual system; `art-direction` makes its imagery and `logo-design` its mark.
4. `web-design`, `collateral-design`, `motion-design` and `product-film` apply that system.
5. `design-principles` supplies a universal craft layer.
6. A prescribed `.agents/` document graph carries brand, strategy, visual system and asset libraries. Product marketing is an external read-only source.

Useful composition: collect accepted identity once, preserve ownership, separate system definition from applications, place actual approved assets, record implementation decisions, and distinguish reusable identity from one-off decoration.

Conflicting composition: always-run brand entry, mandatory three-document gate, prerequisite emotional target plus muses, external copywriting/marketing methods, numeric competitor scorecards and several brand-lead/owner approval stages. These must not replace the existing single Guide entry, task routing, canonical sources or standing authorization. Current context can be sufficient without files named `.agents/brand.md` and `.agents/design.md`.

## Integration routes and observable outcomes

### New design-brand-system

Use when the requested result is a reusable identity system or bounded identity diagnosis across contexts. Inputs: actual assets or supplied brief, audience/purpose/intended qualities, accepted fixed decisions and requested uses. Finish: inspectable system with semantic roles, appropriate assets, fixed/flexible limits, actual application proof and traceable remaining evidence gaps.

Keep open-ended business positioning and naming outside scope; keep logo construction with its independent owner, images with their native/art-direction route, and files with their format capabilities. Do not send every minor design request through a brand exercise.

The candidate package created in the canonical personal-skill authoring workspace contains one main method and three references: identity-direction, collateral-system and sources. Its references retain the useful evidence/identity/collateral distinctions without embedding the upstream lifecycle.

### New motion-design

Use when the requested result changes real UI motion: hover, focus, selection, scrolling, transitions, spatial explanation or repeated interaction behavior. Start from the actual surface, selected object and user action. Specify initial/resting state, trigger, transition, interruption/reversal and final state. Keep user control and reduced-motion behavior explicit. The original implementation/owner route still supplies authority and integration; do not stop after a motion specification when code is requested.

Film/MP4 requests remain visual-storytelling. A generated state sequence or static screenshot is not a live animation test.

### Reuse existing methods

- image-art-direction: add the reusable imagery-library branch only when a series or library needs one; ordinary image creation stays direct.
- design-ui-improvements / audit-ui-ux: retain current task-centric density and visual evidence; source-specific reference matching is conditional on actual brief.
- visual-storytelling: add product-film detail to its existing motion reference, preserving renderer choice and source truth.
- Native artifacts: use the actual document, presentation, PDF, image or website route; one format request does not need a new collateral project.
- Custom logo-design: preserve its separate source and current stronger production/variant model.

## Concrete failure modes to avoid importing

### Authority and source ownership

Mandatory upstream document names, automatic repeated workshops, approval chains and brand-lead escalation are process defaults for that suite. They do not establish our source owners or override current user authorization. No new service signup, model training, credential setup, publishing, sharing or recurring task is authorized merely by a design method.

A live header reveals the deployed logo; it does not automatically supersede an approved source asset. Cross-medium applications must select the actual current variant and inspect the rendered use, without incidental redraws.

### Contextual aesthetic judgments

Treat font choices, palette-stop counts, button shapes, 8-column grids, logo position, motif count, whitespace, type ratios, motion amplitude and printed backgrounds as contextual decisions. Avoid adding these as universal numerical gates or banning a user's requested design solely because it differs from an upstream taste rule.

A neutral reference/preview stage can improve comparison, but a mandatory viewer, social animation or patterned background adds work and can conflict with the actual requested format.

### Technical and internal inconsistencies

- README says Creative Direction caps other audit scores; current brand main/reference explicitly says it does not.
- Brand scoring says 1–5 while Style Guide permits 0; main/reference disagree about whether appetite is asked before the scorecard.
- Stylescape instructions request and forbid typeface tabs; reference-only images and intended assets are not always cleanly separated.
- Motion main/floor prohibit raw linear easing, while the UI toolkit permits continuous mechanical/spinner/marquee motion.
- Fade-only is prohibited as a general move but explicitly used as reduced-motion fallback.
- Transform/opacity-only claims coexist with mask, clip, background-color and filter examples. Compositor-friendly preference is useful; cost and behavior still need actual measurement.
- Motion eval 3 asks for slow premium animation on Delete account, although the main method correctly says functional interaction should stay utilitarian. Do not infer an animation from luxury language alone.
- Collateral tells the author both to keep identity typography/coordinates exact and to vary media/motifs unconditionally. Real output constraints and accepted rules take precedence.
- Print main/checklist suggests CMYK for printing broadly; print.md more appropriately distinguishes screen/office printing from an actual commercial press.
- Collateral's no-logo-on-social and off-canvas radial rules conflict with other in-suite rules or contexts that require a mark/centered card-back motif.
- A provider tool being listed does not prove availability or export correctness.

### Units, previews and checks

The viewer's `96 / dpi` scale can represent a nominal physical size in CSS units for raster-native artboards; it does not establish true physical screen dimensions. [W3C CSS Values and Units 4, section 6.2](https://www.w3.org/TR/2024/WD-css-values-4-20240312/#absolute-lengths) explicitly distinguishes unit ratios from physical measurement on screen. Preserve file dimensions, units and export evidence; use calibration or a true-size print proof when required.

The `px / dpi * 72` type conversion applies only when those pixels are truly the raster artboard's source units at the specified placed size. It must not be copied as a universal formula for CSS font-size or vector PDF text; CSS pixel units already have their own fixed ratio to points. Check the actual format's representation.

A DOM bounding-box audit does not detect every clipping, glyph or semantic problem. Its coverage and a known failure matter, but it cannot replace rendered inspection. A viewer must not become a second source of artwork.

Product-film's verify.py prints tags, duration, a single color sample and seam differences; it does not enforce thresholds or exit on a failed criterion. It is not an acceptance gate. The sample also assumes a decode matrix/range; inspect real metadata and playback before converting, and do not diagnose every washed-out file as the same cause.

A smooth sampled loop need not duplicate its endpoint: assess the wrap transition and continuous playback rather than universally requiring last and first discrete samples to be identical. If color tolerances matter, define the space, metric, sampling region and encoding context; do not impose upstream DeltaE/per-channel thresholds on every film.

Changing codec tags alone does not establish color correctness. Remotion, ffmpeg, browser decoders, profile/transfer handling and final destinations require their actual version-specific validation. No bundled script or command was executed by this review.

Do not fabricate customers, product facts, historic evidence or unsupported claims. Do not copy an upstream blanket prohibition into a stricter general policy than the task requires.
