# Install with durable files

Use this adapter from [INSTALL.md](../INSTALL.md) when the user chooses files or Git. No Notion account or native skill registry is required. Discover an existing durable location before asking for one; do not invent an OS path or modify global host instructions without knowing their owner.

1. Reuse the user's existing Guide, work index and distribution record where they serve the same functions. Otherwise create them at the chosen private durable destination using the [Guide](../distribution/workflow-starter/templates/Agent-Operating-Guide.md), [index](../distribution/workflow-starter/templates/Work-index.md) and [distribution record](../distribution/workflow-starter/templates/Distribution-record.md) templates. Preserve existing personal settings. Do not commit these private values to this public repository.
2. Keep a dedicated immutable source snapshot at the selected commit. A Git checkout, verified extracted bundle or supported immutable remote source is acceptable when the host can read it in future sessions. For local/offline use, retain the complete source layout so relative links from `docs/` to `skills/` and `guidance/` still work. If the host cannot reliably read a remote source, save a verified durable local copy before activating it. Do not point future sessions at scratch or a moving branch.
3. Fill the Guide with actual paths or immutable source URLs for the kernel, work cycle, context entry, method router and catalog. Record the exact source commit and both source versions. With a bundle, derive them from `BRONNEN.json`; otherwise read the selected checkout. Mark services, memory storage, recurring maintenance, external extensions and Notion setup **not configured** unless the user already chose and authorized them.
4. Supply the complete base collection through file access. Read `skills/catalog.json`; preserve each whole `skills/<name>/` directory and invocation policy. If a native host installation is also requested, follow [SKILL-WORKFLOW.md](SKILL-WORKFLOW.md) using that host's documented destination and save/readback process. Do not guess a global skills directory or call copied files a native installation.
5. Merge the filled [personal entry rule](../distribution/workflow-starter/templates/Personal-entry.txt) into the host's own supported instruction mechanism. Keep all unrelated instructions. If the host provides no write capability, deliver the ready text and mark that precise account step pending. A Guide file alone does not cause automatic host loading.
6. Read back the saved files and follow every required link. Check package hashes against the selected source, and verify one existing project route without moving its tasks. Repeat the installation comparison to check reuse, then exercise a simple answer and a missing-capability case. A new-session check requires an actual fresh context; otherwise record it as pending.

Restore through the existing distribution record: revert only installation-owned additions or bounded patches using the saved old content; compare again if user changes occurred later. Do not reset a user's full folder or repository. File access and native-host installation have separate acceptance states.
